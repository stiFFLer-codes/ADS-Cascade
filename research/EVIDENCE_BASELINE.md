## Note 1 — the A5 dominant-account-selection bug (FIXED 2026-08-11 — applies historically to the superseded rows above, and still applies to unverified production figures)

`scripts/03_5_dataset_intelligence.py`'s per-product dominant-account selection
(`product_ambiguity.csv`, Module C.1) picked the single largest mapping *row* rather than the
largest *account total* — a real, verified bug (full evidence in
`research/determinism_provenance.md` Step 3). It **understated** determinism for multi-company
products only (single-company products are mathematically unaffected).

**Status: fixed.** A regression test was written first (`scripts/test_dataset_intelligence.py`,
watched to fail against the pre-fix code), then the aggregation logic was corrected to sum counts
by `account_id` before selecting the dominant account (matching the pattern the neighboring C.3
block already used correctly). The synthetic pipeline was re-run end-to-end on the same,
unmodified input data. Full details: `research/a5_correction_analysis.md`.

| | Superseded (pre-fix) | **Canonical (post-fix, current)** |
|---|---|---|
| Unweighted ADS | 0.9310 | **0.9597** |
| Weighted ADS | 0.8094 | **0.9031** |
| Products >0.95 deterministic | 84.12% (710/844) | **87.56% (739/844)** |

**None of the five architecture decisions changed** under the correction, confirmed by actually
re-running the pipeline (not estimated) — see `a5_correction_analysis.md` §5. R1 and R3 are the
only decisions close enough to a threshold to matter; both reproduce identical decisions
post-fix, with narrower margins.

Any manuscript text that cites the *synthetic* weighted/unweighted ADS gap (§3.2's table) must be
updated to the corrected values above — see `a5_correction_analysis.md` §7 for the exact
`TECHNICAL_REPORT.md` lines affected. This document does not edit the manuscript; it only
establishes what the corrected pipeline now produces.

Whether the same bug affected the **production** numbers (91.2%, 0.847, 0.964) similarly still
cannot be verified from this repository — the confidential production data isn't here, and those
figures were generated by the pre-fix script version. Those production rows in §1 above remain
flagged "likely understated, unverified" until the author re-runs production data through the
corrected code. Reasoning for why the same *direction* of effect is plausible in production too is
given in `research/determinism_provenance.md`, but it is explicitly labeled there as unverified
reasoning, not a finding.

## How to use this document

- When writing the manuscript, cite the metric from the table above, and use the **Source artifact**
  column for the in-repository reference, not a hand-picked file.
- If a number carries a Note 1 caveat, either (a) it's a **production** figure — cite it with the
  "likely understated, unverified" caveat sentence attached, since production can't be re-run here;
  or (b) it's a **synthetic** figure — Question F6 is resolved, the bug is fixed, cite the corrected
  post-2026-08-11 value directly, no caveat needed.
- Any value marked `SUPERSEDED — DO NOT CITE` (§2, §3) must not appear in the manuscript in any
  form, including as a "previously reported" aside — use the corrected value next to it instead.
- This document reflects the state of the pipeline and its committed outputs as of 2026-08-11
  (post A5-fix). If any script or committed CSV changes after this date, this baseline needs to be
  regenerated, not assumed to still hold.
